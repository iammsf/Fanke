# SEO 优化器

文章编辑器内的 SEO 检查与 AI 建议面板：本地规则实时评分，AI 标题/摘要建议和选中段落润色都必须手动确认后才写回编辑器。

## 功能

- 编辑器面板：声明 `addEditorPanel` 后出现在文章编辑器「扩展工具」中，以 iframe 打开 `index.html?panel=1`；宿主通过 postMessage 推送标题、摘要、正文、选中文本和文章 ID。
- 标题检查：按 Unicode 字符统计标题长度，低于或超过阈值时给出提示。
- 摘要检查：同样按字符统计摘要长度，低于或超过阈值时给出提示。
- H1 检查：用正则统计正文 HTML 中的 `<h1>` 标签，0 个提示缺少，超过 1 个提示过多。
- 图片 Alt 检查：统计 `<img>` 标签，缺少 `alt` 属性的图片计入问题；`alt=""` 也会被视为已填写。
- 可读性检查：去掉 HTML 标签后，以 `。.!！?？` 的出现次数作为句数，计算「100 − 平均每句字数 ÷ 5」，最低为 0。
- 总分：从 100 起扣分，标题问题 −15、摘要问题 −15、H1 问题 −10、缺 Alt 每张 −5（最多 −20）、可读性低于 50 再 −10，最低为 0；80 分以上绿色、60 分以上黄色、其余红色。
- 本地通过提示：标题、摘要、H1 均无问题、没有缺 Alt 图片且可读性不低于 60 时显示「本地检查全部通过」。
- AI 深度分析：标题或正文至少一项非空才能发起；正文去标签后截取前 12000 字符；提示词要求 3 条标题、2 条摘要、3–8 个关键词、2–4 条正文建议和 2–4 条结构建议，每条不超过 80 字；调用参数为 `temperature: 0.4`、`max_tokens: 1600`。
- 结果展示：标题与摘要建议逐条提供「应用」，关键词以标签展示，正文与结构建议只读展示；AI 返回不是合法 JSON 或没有可用字符串时显示空结果提示。
- 应用与撤销：应用只写标题或摘要；同一字段只保留一条已应用记录，按钮变为「撤销」，顶部显示已应用字段并支持「全部撤销」；应用后不会清空 AI 结果，可以继续应用其它建议。
- AI 润色：必须先选中正文，且单次不超过 4000 字；提示词要求返回 JSON `{"candidates":["候选1","候选2"]}`，调用参数为 `temperature: 0.5`、`max_tokens: 1600`。
- 润色确认：候选与原文用公共前后缀做粗粒度差异对比（红色删除、绿色新增），应用后替换编辑器中的选中内容；同一时间只保留一条润色结果，可撤销。
- 通知降级：AI 失败优先通过宿主 `notify.send` 以弹出框展示每条连接的分组/模型与报错，调用失败时回落到面板内 toast。
- 不直接保存文章：所有建议都通过 postMessage 写入宿主编辑器，最终保存仍由用户在编辑器中完成。

## 安装

- 在后台「插件」页上传 `.zip` 安装包；插件没有 `server/` 子进程，也不需要额外系统命令。
- 安装包可由 `deploy/install.sh` 生成到 `/opt/fanke/dist/extensions/seo-optimizer.zip`；该脚本只对含 `go.mod` 和 `server/` 的插件编译服务端，本插件会被直接打包。
- 包内必须包含 `index.html` 与 `init.ts`（或 `init.js`）；宿主安装时会先把 TypeScript 编译为同名 JavaScript，`index.html` 引用的 `./app.js` 由此生成。
- 上传成功后会跳转到插件详情页，需要点击初始化：插件会请求创建专属数据表并写入默认配置，完成后才标记为已初始化。
- 初始化时宿主会弹出建表确认；拒绝创建会导致初始化失败，插件不会进入可用状态。
- AI 功能要求后台至少配置一条已启用的 AI 连接，否则 `ai.chat` 会返回无可用连接错误；AI 连接本身不在本插件内配置。

## 配置

在插件详情页（非 panel 模式）配置四个阈值：

| 字段 | 默认值 | 校验与说明 |
| --- | --- | --- |
| 最小标题长度 `min_title_length` | 10 | 1–100 的整数 |
| 最大标题长度 `max_title_length` | 60 | 1–100 的整数 |
| 最小描述长度 `min_description_length` | 50 | 1–500 的整数 |
| 最大描述长度 `max_description_length` | 160 | 1–500 的整数 |

- 保存时还会校验最小长度不能大于最大长度；非法值会提示「长度必须是范围内的整数」或「最小长度不能大于最大长度」。
- 「保存配置」写入 `seo_config`；「恢复默认」把四项恢复为 10/60/50/160 并立即保存。
- 初始化模式下保存与恢复按钮会被禁用，避免在初始化完成前改写配置。
- 本插件没有单独的规则开关，四项阈值就是全部可配置规则；也没有 AI 连接、模型或密钥配置。
- AI 分析不指定分组或模型，由宿主按后台保存的「当前使用」连接执行；没有选择时按启用连接的权重负载均衡。

## 声明的能力与 Hook

`info.json` 未声明 `capabilities`，只声明以下 `request`：

| 类型 | 名称 | 用途 |
| --- | --- | --- |
| request | `store.ensure_table` | 创建本插件专属数据表，宿主会先向管理员确认 |
| request | `store.get` | 读取 `seo_config` 阈值配置 |
| request | `store.save` | 保存 `seo_config` 阈值配置 |
| request | `ai.chat` | 调用后台 AI 连接生成 SEO 建议与润色候选 |
| request | `notify.send` | 让宿主以全局/区域内/弹出框形式展示成功或失败通知 |
| request | `addEditorPanel` | 在文章编辑器「扩展工具」中注册面板入口 |

- `ai.chat` 的宿主限制：最多 50 条消息、消息总长不超过 20 万字符、`temperature` 0–2、`max_tokens` 0–32000。
- `notify.send` 的宿主限制：消息不超过 2000 字、标题不超过 120 字，`scope` 支持 `global`、`inline`、`modal`。

## 数据存储

- 数据保存在插件专属表 `ext_data_seo_optimizer`（表名由 slug 把 `-` 换成 `_` 后加 `ext_data_` 前缀得到），结构为 `k` 唯一键、`v` JSONB、时间戳。
- 目前只使用一个键 `seo_config`，值为四项阈值组成的 JSON；初始化时若不存在会写入默认值。
- 不存储文章标题、正文、摘要或 AI 返回内容；编辑器内容只在该 iframe 的内存状态中处理。
- 不存储任何密钥；AI 凭证保存在宿主的 AI 连接配置中，插件只能通过 `ai.chat` 间接调用。
- 该表仅本插件可读写；插件没有申请公开的 `store.get_batch`，阈值配置不会通过该 hook 暴露给访客。

## 使用方式

- 在后台「插件」页安装、初始化并启用后，进入文章编辑器，从「扩展工具」打开 SEO 优化器面板。
- 面板打开后等待宿主推送内容，分数和本地检查会随标题、摘要、正文变化自动刷新。
- 点「开始分析」发起 AI 深度分析；分析期间按钮显示「分析中…」，完成后逐条查看建议。
- 点击标题或摘要建议旁的「应用」写入编辑器，按钮变为「撤销」；可继续应用其它建议，或点「全部撤销」还原本轮的标题/摘要。
- 在正文中选中一段文字后点「润色选中内容」；对比候选差异，确认后替换选中内容，点「撤销」调用宿主撤销上一处内容改动。
- 规则阈值在插件详情页调整；保存后新打开或重新加载的面板会使用新阈值。

## 安全与限制

- AI 分析会把标题、摘要和正文前 12000 字符发送给后台配置的 AI 服务；润色会把选中的最多 4000 字符发送出去，请勿在不可信的 AI 连接下处理敏感内容。
- AI 输出被视为不可信文本：建议以 `textContent` 渲染，差异对比会转义 HTML，只接受字符串数组，不会执行模型返回的 HTML。
- 本地检查是启发式规则：H1 与 Alt 用正则匹配原始正文 HTML，不解析 DOM；可读性只按标点估算，不代表搜索引擎真实评分。
- 面板不会自动修改文章；所有写回都要求用户点击「应用」或「撤销」，且标题/摘要为空时不会写入（撤销时允许写回空值）。
- 新一轮 AI 分析会重置上一轮的「应用/撤销」状态，但不会自动还原已经写入编辑器的内容。
- 润色一次只保留一个已应用候选；撤销依赖宿主编辑器的撤销栈，若期间进行了其它正文修改，撤销目标可能与预期不同。
- AI 调用失败不会破坏本地检查功能，面板仍可用于规则评分；错误会通过宿主通知或本地 toast 展示。
- 阈值只接受整数，避免负数或异常大的配置导致检查结果不可读。
