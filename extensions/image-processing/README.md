# 图片处理

上传图片时保留原图，按可配置的宽度列表生成等比、不放大的 WebP 派生图，供前台缩略图与正文图片使用。

## 功能

- 上传时（插件已启用、处理开关已开启）为静态 JPEG、PNG、WebP 图片生成多档 WebP 派生图，原图始终保留。
- 目标宽度列表可配置 1–8 个值，保存时自动去重并按升序排列；生成时宽度大于原图的档位会收敛到原图宽度，然后停止，因此不会放大图片。
- 派生图按原图宽高比计算高度（向下取整，最小 1 像素），不裁剪主体。
- 动画 PNG、动画 WebP 及其他不支持的格式不会生成派生图（上传继续，响应带 `warning`）；GIF、SVG 等不在可转码扩展名范围内的文件也不会生成派生图。
- WebP 质量可配置为 1–100 的整数，默认 82；服务端对非正数质量回退为 82。
- 派生图保存为独立媒体派生记录，默认前缀 `_media_variants/<sha256>/<媒体 id>/<文件名>-<宽度>w.webp`，与原图使用同一存储位置（本地或 S3）。
- 上传生成或落盘失败时原图不会丢失：响应仍返回原图，并附带 `warning`（如「原图已保留，图片处理失败: …」）；已成功生成的档位会被保留。
- 前台 `/img?src=…&w=…` 缩略图端点优先返回已登记的派生图；未命中时按需调用 `cwebp` 生成并缓存，失败则 302 回原图，页面不会出现打不开的图片。
- 删除原图时媒体删除流程会联动删除其派生图；S3 存储转移也会同步迁移派生图记录。
- 仅在插件详情页配置，开关关闭时后续上传不做处理；停用插件不会删除已有派生图。

## 安装

后台「插件」页上传 `.zip` 安装包。安装包可由 `deploy/install.sh` 生成到 `/opt/fanke/dist/extensions/image-processing.zip`，也可在 `extensions/image-processing/` 下将目录内容打包为 zip 上传。

该插件是可信服务端插件，真实依赖如下：

- 服务器已安装 `cwebp`（Debian/Ubuntu 的 `webp` 包，RHEL 系的 `libwebp-tools`）；`deploy/install.sh` 会自动安装对应软件包。
- 安装包内包含当前系统/架构的服务端二进制 `server/bin/<goos>-<goarch>/image-processing-server`；`deploy/install.sh` 会编译 `server/main.go` 并打包。
- 启用插件时后端会检查 `cwebp` 是否存在，缺失会拒绝启用并提示 `missing plugin dependency: cwebp`；缺少服务端二进制则 manifest 校验不通过。
- 上传后需先在详情页完成初始化，之后才能启用；启用可信程序时会弹出确认，提示其以博客服务账号运行。

## 配置

插件详情页通过同源 `postMessage` 读取和保存配置（对应后端 `GET/PUT /admin/media/image-processing`），字段如下：

| 字段 | 说明 | 默认值 | 取值范围 |
| --- | --- | --- | --- |
| 开启上传图片处理 | 是否在后续上传时生成派生图 | 关闭（迁移写入 `{"enabled":false}`） | 布尔值 |
| 目标宽度列表 | 要生成的 WebP 宽度，逗号分隔 | `480, 740, 1080` | 1–8 个唯一正整数，每个 16–8192 |
| WebP 质量 | `cwebp -q` 的质量参数 | `82` | 1–100 的整数 |

- 前端会按逗号、中文逗号或空白拆分宽度，去重并升序；前端校验宽度为正整数、质量为 1–100，8 个上限与 16–8192 范围由后端二次校验，不满足时保存返回错误。
- 读取配置时后端也会做归一化：过滤超范围宽度、去重、升序、超过 8 个截断；宽度为空则回退默认列表，质量越界则回退 82。
- 页面提供「保存图片处理设置」「重新读取」「重试读取」；重新读取前会确认是否丢弃未保存修改，配置请求超时为 30 秒。
- 插件声明 `addSettingsItems` 后，后台「设置」页会出现「图片处理」配置卡片，点击跳转到 `/admin/plugins/image-processing`；实际保存仍由详情页 iframe 完成。

## 声明的能力与 Hook

`info.json` 的 `request` 共 2 项，`capabilities` 为 `image.process`。

| 名称 | 类型 | 用途 |
| --- | --- | --- |
| `beforeMediaUpload` | 生命周期事件 | 订阅媒体上传前置事件；声明是后端启用本插件处理器（`processImageUpload`）的前提，未声明时该处理器在 `activeMediaPlugins` 中会被置空 |
| `addSettingsItems` | 声明式扩展点 | 在后台设置页挂载「图片处理」配置入口；未声明则不展示该设置卡片 |
| `image.process` | 服务端能力 | 宿主缩略图与派生图流程通过插件 RPC 调用服务端二进制的 `image.process`，执行 `cwebp` 转码 |

清单中的其他服务端字段：

| 字段 | 值 | 用途 |
| --- | --- | --- |
| `protocol_version` | `1` | 插件 RPC 协议版本，必须与宿主一致 |
| `trusted_process` | `true` | 以可信本地进程方式运行服务端程序 |
| `entrypoint` | `server/bin/${goos}-${goarch}/image-processing-server` | 服务端二进制路径模板，按当前平台替换 |
| `dependencies` | `["cwebp"]` | 启用时检查的命令依赖 |

## 数据存储

- 配置不写入插件 KV 表，而是保存在宿主系统设置表 `settings` 的 `media_image_upload` 键中，结构为 `{"enabled":bool,"widths":[int],"quality":int}`。
- 派生图元数据写入 `media_variants` 表：关联原图媒体 id，记录宽度、高度、存储类型、对象 key、URL 与文件大小。
- 派生图文件与原图存放在同一存储：本地存储落在媒体目录，S3 存储落在同一桶的 `_media_variants/` 前缀下。
- 本插件没有调用 `store.ensure_table` 或其他 `store.*` hook，不创建自己的插件数据表。

## 使用方式

1. 安装并初始化插件后，在详情页开启「开启上传图片处理」，填写宽度列表与质量，点击保存。
2. 之后在媒体库上传图片（可选择本地或 S3 桶），原图正常入库，同时在后台生成配置中的各档 WebP。
3. 前台缩略图与正文图片统一走 `/img` 端点：命中已有派生图直接返回，未命中则按需生成；客户端不支持 WebP 时直接回原图。
4. 修改宽度或质量只影响后续上传与后续按需生成，不会重新处理已有媒体；关闭开关同样不删除已有派生图。
5. 删除原图会连同派生图一起删除；在存储间转移媒体时派生图记录随原图一起迁移。

## 安全与限制

- 仅处理静态 JPEG、PNG、WebP；动画 PNG/WebP、GIF、SVG 及其他格式不生成派生图，避免丢失动画或产生不支持的编码。
- 宽度列表最多 8 项、单项 16–8192，质量必须为 1–100；配置读取会静默归一化，但保存接口会拒绝非法值。
- 上传本身受宿主限制：图片及其他附件最大 100MiB，视频最大 1GiB；本插件只读取已通过宿主校验的图片数据。
- 转码依赖服务器 `cwebp`；`cwebp` 缺失、执行失败或源图超出限制时，原图保留并返回 `warning`，`/img` 端点也会降级为 302 原图。
- 使用 S3 时如果桶的内容类型策略不允许 `webp`，该次派生图生成会被放弃并提示「桶策略不允许 WebP」，原图仍正常保存。
- 派生图会增加磁盘或对象存储占用；处理失败不会阻断上传，但需要根据响应中的 `warning` 排查。
- 该插件声明为可信服务端进程，会以博客服务账号执行本机命令；只应启用来源可信的安装包。
