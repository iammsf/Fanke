# 图片焦点选择器

为媒体库图片标注展示焦点，缩略图按容器宽高比自动选择取景区域，避免裁切时切掉图片重点。

## 功能

- 在媒体库「管理」模式下，每张图片卡片多出「选择焦点」按钮（仅当插件已启用且文件 MIME 以 `image/` 开头）。
- 焦点编辑器提供 1:1、16:9、9:16 三个虚线取景框和一个 `⊙` 中心点；中心点、框体均可拖动，框右下角手柄等比例缩放，`↺` 可把单个框重置为默认位置。
- 所有坐标以 0–1 的归一化值保存，与图片实际像素尺寸无关；缩放与拖动时会按图片自然宽高比校正，框宽最小为 0.04，且不会越出图片。
- 前台组件按容器宽高比挑选取景框：宽高比 0.85–1.18 用 1:1 框，1.55–2.05 用 16:9 框，0.48–0.68 用 9:16 框；其余比例、无匹配框、框仍是内置默认值或几乎覆盖整图时，改用中心点 `(cx, cy)`。
- 计算 `object-position` 时会结合容器比例与图片实际比例，而不是简单取框中心百分比，保证 `object-fit: cover` 下框中心对准图片像素。
- 插件详情页提供媒体库扫描初始化、记录/图片统计、JSON 导入导出、重复记录清理、无效链接检测与批量删除。
- 首次安装的 `init` 脚本只负责建表（幂等），扫描媒体库需在详情页手动点击。

## 安装

后台「插件」页上传 `.zip` 安装包。安装包可由 `deploy/install.sh` 生成到 `/opt/fanke/dist/extensions/image-focus.zip`，也可在 `extensions/image-focus/` 下将目录内容打包为 zip 上传。

- 无服务端程序、无 Go 依赖、无外部命令依赖。
- 包内 `.ts` 文件会在安装时自动编译成同名 `.js`，无需自行构建。
- 上传后需在插件详情页完成初始化（`init.ts` 自动调用 `store.ensure_table` 建表），之后才能启用。

## 配置

本插件没有开关或配置字段。

- 默认焦点为内置常量：中心点 `cx=0.5, cy=0.5`；1:1 框 `{x:0.25, y:0.25, w:0.5, h:0.5}`；16:9 框 `{x:0.1, y:0.21875, w:0.8, h:0.45}`；9:16 框 `{x:0.275, y:0.1, w:0.45, h:0.8}`。
- 默认值只在「扫描媒体库并初始化」时写入缺失记录，或在新图片第一次打开焦点编辑器时作为初始值；不提供全局修改默认值的界面。

## 声明的能力与 Hook

`info.json` 的 `request` 共 12 项，均为能力 API；本插件不声明 `capabilities`。

| 名称 | 用途 |
| --- | --- |
| `store.ensure_table` | 首次初始化时创建本插件的数据表（`init.ts`） |
| `store.save` | 焦点编辑器保存单张图片的焦点数据 |
| `store.get` | 打开焦点编辑器时读取该图片已有焦点 |
| `store.get_batch` | 前台 `FocusImg` 批量读取焦点（公开 hook，匿名可读） |
| `store.list` | 无效链接检测时读取全部记录 key |
| `store.import` | 媒体库扫描补默认焦点、导入备份文件 |
| `store.export` | 导出全部焦点记录为 JSON |
| `store.dedup` | 删除重复 key 的历史脏数据（兜底） |
| `store.delete` | 删除检测出的无效记录 |
| `store.stats` | 详情页显示焦点记录总数 |
| `media.list` | 按 `image/` 前缀扫描媒体库图片、统计图片数量 |
| `http.check_url` | 服务端批量探测图片链接可达性（每批最多 100 条） |

## 数据存储

- 使用宿主插件 KV 表 `ext_data_image_focus`（表名由 slug 派生，`-` 替换为 `_`）。
- 每张图片一条记录：key 为媒体库中的图片 URL（`media.url`），value 为焦点对象 `{cx, cy, square, wide, tall}`，三个框各含 `{x, y, w, h}`。
- 数据完全存于该表；扫描统计、导出、去重都直接操作这张表，不存在额外配置文件或本地存储。

## 使用方式

1. 启用插件后进入后台「媒体库」，在图片卡片上点击「选择焦点」。
2. 在弹出对话框中拖动 `⊙` 或虚线框：按住虚线边缘移动，拖右下角手柄等比例缩放，点 `↺` 重置单个框。
3. 点右侧 `✓` 保存（写入当前 `media.url`），点 `✕` 取消；保存后前台立即使用新焦点。
4. 前台文章封面、媒体库缩略图等使用 `FocusImg` 组件时自动读取焦点；未启用插件或该图无数据时等同普通 `<img>`（`object-position` 为默认 `50% 50%`）。
5. 插件详情页可依次执行：① 扫描媒体库并初始化；② 查看数据统计；③ 导出 / 导入 / 去重；④ 检测并清理无效链接。

## 安全与限制

- `store.get_batch` 是公开 hook：插件启用后，焦点记录（图片 URL 与归一化坐标）对匿名访客可读，不要在该表写入敏感信息。
- 媒体库扫描调用 `media.list`，最多返回 5000 条且无分页；图片数量超过 5000 的站点只能覆盖前 5000 张。
- 扫描使用 `overwrite: false`，只补缺失记录，不会覆盖用户已调整过的焦点。
- 无效链接检测会同时做浏览器 `new Image()` 探测（并发 8，单条 6 秒超时）与服务端 `http.check_url` 探测；两者都不可达才判定为无效，避免单侧网络策略导致误删。
- 服务端探测站内相对路径直接视为可达，外部地址仅支持 `http://` / `https://`；禁用内网与云元数据地址。
- 单次删除受 `store.delete` 限制为最多 1000 个 key；无效记录超过 1000 条时该次删除会失败，需要分批处理。
- 导入接受 `{items:[{key,value}]}` 或直接的数组，也兼容旧版 `{url, focus}` 格式；默认覆盖同名 key，导入前建议先导出备份。
- 删除操作不可恢复；焦点框宽小于 0.04 会被钳制，框体始终被限制在图片范围内。
